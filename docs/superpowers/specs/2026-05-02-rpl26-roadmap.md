# rpl26 Roadmap

## Project Name

The project name is `rpl26`. The local checkout directory may still use an older name, but code, scripts, package metadata, and planning docs should use `rpl26`.

## Scope Rule

`rpl26` is a clean-room HP 48 User RPL-inspired object-stack language and calculator runtime. The HP 48G Series manuals are the preferred behavior baseline because they keep the project centered on User RPL rather than CAS-era HP 49/50 features. CAS, symbolic algebra, equation solving, matrices, plotting, and HP ROM compatibility stay out of the early roadmap. Units are a dedicated later milestone because they are a core part of the HP 48 experience but need their own object model and manual audit.

## Numeric Backend Rule

The core runtime stays in TypeScript and uses JavaScript `number` for early real-number behavior. Richer numerical backends are deferred until a concrete command family requires them, and they should sit behind an internal boundary rather than replacing the RPL runtime. See [Numeric Backend Strategy](2026-05-02-numeric-backend-strategy.md).

## Milestones

### Milestone 1: RPL Identity Slice

Persistent object stack, strict parser, programs as objects, `EVAL`, globals via `STO`, local variables via `->`, CLI, REPL, autocomplete, and MCP access.

This milestone proves the core language shape: RPL objects can be parsed, placed on a persistent stack, evaluated through programs, stored in variables, and driven from both humans and agents.

### Milestone 2: Everyday Stack Programming

Manual-derived stack utilities, list construction/decomposition, comparison words, booleans, and a first conditional form.

This milestone makes the language useful for small day-to-day programs without introducing CAS: more stack words, simple list handling, truth values, comparisons, and basic branching.

### Milestone 3: Program Control Flow

Loops, structured branching refinements, program composition helpers, and better runtime errors/traces for multi-step programs.

This milestone turns the evaluator into a more complete programming environment by adding repeated execution, richer control structures, and traces that stay readable as programs get longer.

See [Milestone 3 Design](2026-05-02-milestone-3-design.md).

### Milestone 4: Object Library

More non-CAS object operations for strings, lists, tagged values, display-friendly formatting, and command discovery.

This milestone expands the object system around practical data manipulation while still avoiding symbolic algebra, binary integers, matrices, units, and other large HP subsystems.

Milestone 4 should also pull forward a small command-discovery slice from Milestone 6 so the new object words are easy to explore. See [Milestone 4 Design](2026-05-02-milestone-4-design.md).

### Milestone 5: Manual-Derived Conformance Suite

Source-labeled User RPL examples from public HP manuals, with explicit notes for supported behavior, deferred behavior, and intentional clean-room divergences.

This milestone grounds the implementation in documented User RPL behavior by adding public-manual examples as tests, while keeping each compatibility decision explicit.

### Milestone 6: Usability Surface

Richer REPL ergonomics, command help, searchable word reference, history, saved sessions, and better human-readable stack/trace views.

This milestone makes the runtime pleasant to use directly, so exploration does not require reading source code or parsing large JSON traces.

Deferred TUI help refinement: make the Words pane a real browser/search view where keyboard navigation can filter and select words, and make the Help pane show detail for the selected word. The current Help pane has the state shape for this but needs an explicit keyboard interaction design before implementation.

### Milestone 7: Integration Surface

Named MCP sessions, stable tool schemas, editor/agent integration examples, and a small scripting interface for batch runs.

This milestone makes `rpl26` a dependable backend for agents, editors, scripts, and other clients that need stable machine-facing interfaces.

### Milestone 8: Menu Bar GUI

A small native-feeling menu bar calculator client that talks to the same engine instead of reimplementing calculator behavior.

This milestone gives the calculator a persistent desktop presence: quick stack entry, stack inspection, history, and saved sessions from a menu bar app backed by the shared core/MCP runtime.

### Milestone 9: Units

HP 48-style unit objects, unit arithmetic, unit conversion, and a curated unit catalog based on the HP 48G manuals.

This milestone gives `rpl26` one of the most distinctive HP calculator features while keeping it separate from CAS, matrices, plotting, and binary HP object compatibility. It should start with manual-derived unit syntax and conversion behavior before expanding the catalog.

### Deferred: CAS And HP Compatibility

Symbolic algebra, exact arithmetic, matrices, plotting, full HP command compatibility, System RPL, ROM behavior, and binary object formats remain explicitly deferred until the object-stack runtime is mature.

This deferred bucket protects the project from becoming an HP clone or CAS before the core object-stack language is solid.
